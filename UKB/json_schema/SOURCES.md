# Sources — CD3 pilot: UKB (UK Biobank)

## Dictionary files

All 18 files below are the full UK Biobank Showcase schema export (schema tables 1–3, 5–14, 16–18, 20–21 of 27; tables 4 Returned Datasets, 15 Genotyped SNPs, 19 Publications, 22–27 Resources/Applications and 999 Showcase Service Schema were left undownloaded — not variable dictionaries). Downloaded fresh 2026-09-21 from `https://biobank.ndph.ox.ac.uk/ukb/scdown.cgi?fmt=txt&id=N`, tab-separated, UTF-8, header row 1, originally saved to `Harmonization/Original Cohort Metadata and Schemas/UK Biobank/`, copied to `CD3_Schemify_Pilot/UKB/raw_data/` (matching the BGS/MWS packages' convention). Confirmed byte-identical to the same-day download and to the pre-existing copies in `Harmonization/Harmonised Cohort Schemas (legacy)/CD3_UKB_Schema/raw_data/` — one consistent release.

- `field.txt` (schema table 1, Data Field Properties) · 11,821 data rows, 29 columns (`field_id, title, availability, stability, private, value_type, base_type, item_type, strata, instanced, arrayed, sexed, units, main_category, encoding_id, instance_id, instance_min, instance_max, array_min, array_max, notes, debut, version, num_participants, item_count, showcase_order, cost_do, cost_on, cost_sc`) · the primary variable inventory; one row per field_id · `item_type` splits it four ways: `0` Data (11,271 — ordinary tabular variables, the realistic conversion scope), `20` Bulk (424 — pointers to external bulk files: imaging, raw genetic data, not simple values), `30` Records (112 — stub flags that only announce a participant has rows in a separate linked-record table; the 112 include the 34 tables in `record_table.txt` plus ~78 further stubs for genomics/imputation datasets with no `record_column.txt` breakdown), `10` (14, role not yet checked) · `main_category` joins to `category.txt` (324 distinct categories used) · `encoding_id` joins to `encoding.txt` · registered 2026-09-21. **Routing scan:** signals seen but not itemized at this scale — negative sentinel-like codes recur across hundreds of categorical (`value_type` 21/22) fields (e.g. -1 "Do not know", -3/-818 "Prefer not to answer", -7 "None of the above", -2/-10/-121 assorted not-applicable/never-tried variants — pattern taken from the legacy pipeline's `MISSING_CONVENTIONS`, not yet re-derived here); UK Biobank's questionnaire structure implies many gate-and-detail pairs (an "ever X" flag beside an "age started X" or "X per day" detail) but individual pairs are not enumerated file-wide — deferred to per-category scans at convert time (ROUTING.md), given ~11,000 candidate fields.
- `fieldsum.txt` (schema table 16, Field Summary) · 11,646 data rows, 3 columns (`field_id, title, item_type`) · a strict subset of `field.txt`'s same three columns (every fieldsum field_id is in field.txt; 175 field.txt field_ids, e.g. 189, are absent from fieldsum — reason not yet investigated) · registered 2026-09-21, kept only as a cross-check, not a primary source.
- `encoding.txt` (schema table 2, Encoding Dictionaries) · 858 data rows (`encoding_id, title, availability, coded_as, structure, num_members, descript`) · lists every code-list referenced by `field.txt`'s `encoding_id`, but not the codes themselves — `coded_as` says the value type (integer/string/real/date) and `structure` says flat/hierarchical, which routes to one of the six value tables below · registered 2026-09-21.
- `category.txt` (schema table 3, Categories) · 410 data rows (`category_id, title, availability, group_type, descript, notes`) · titles and descriptions for `field.txt`'s `main_category` and for every node in `catbrowse.txt`'s tree · registered 2026-09-21.
- `catbrowse.txt` (schema table 13, Category Browse Tree) · 362 data rows (`parent_id, child_id, showcase_order`) · the category hierarchy edges. Confirmed a strict tree, not a DAG — every category has exactly one parent, so category names/paths are unambiguous · 8 true top-level roots (categories that are never a child): `1` Population characteristics, `91` Health outcomes, `523` Cardiac image-derived phenotype classifications, `100000` Assessment centre, `100078` Biological samples, `100088` Additional exposures, `100089` Online follow-up, `100314` Genomics · registered 2026-09-21.
- `instances.txt` (schema table 9, Instancing Dictionaries) · 12 data rows (`instance_id, descript, num_members`) · describes what a field's `instance_id` means as a group (e.g. "repeated across assessment visits") · registered 2026-09-21.
- `insvalue.txt` (schema table 10, Instance Values) · 33 data rows (`instance_id, index, title, descript`) · the per-index labels within an instancing dictionary (e.g. instance_id 1, index 0 = "clinic", "Conducted in assessment centre, April 2009 to September 2010") · registered 2026-09-21.
- `esimpint.txt` (schema table 5, Simple Integer Encodings) · 18,078 data rows (`encoding_id, value, meaning, showcase_order`) · code→label pairs for flat integer-coded fields · registered 2026-09-21.
- `esimpstring.txt` (schema table 6, Simple String Encodings) · 439,346 data rows, same 4 columns · by far the largest file (18.8 MB) — flat string-coded fields, e.g. free-text-derived code lists (drug names, addresses) · registered 2026-09-21.
- `esimpreal.txt` (schema table 7, Simple Real Encodings) · 17 data rows · registered 2026-09-21.
- `esimpdate.txt` (schema table 8, Simple Date Encodings) · 18 data rows · registered 2026-09-21.
- `esimptime.txt` (schema table 20, Time Encodings) · 3 data rows · registered 2026-09-21.
- `ehierint.txt` (schema table 11, Hierarchical Integer Encodings) · 28,900 data rows (`encoding_id, code_id, parent_id, value, meaning, selectable, showcase_order`) · coding trees such as ICD-10, ICD-9, OPCS-4 procedures, occupation (SOC) — `selectable` marks leaf vs. header nodes · registered 2026-09-21.
- `ehierstring.txt` (schema table 12, Hierarchical String Encodings) · 46,927 data rows, same shape with string `value` · further coding trees (e.g. Read/CTV3 clinical codes, treatment/medication) · registered 2026-09-21.
- `recommended.txt` (schema table 14, Field Recommendations) · 1,975 data rows (`category_id, field_id`) · which fields the Showcase interface highlights per category — a hint for category proposal, not a primary variable source · registered 2026-09-21.
- `related.txt` (schema table 21, Field Linkages) · 9,280 data rows (`field_lo, field_hi, description`) · prose cross-references between fields, e.g. "F3081 indicates which foot is described in F19" or successor/predecessor notes. **Routing scan:** a plausible source of implied routing/successor relationships between fields; not yet mined for skip logic — flagged for the per-category scan.
- `record_table.txt` (schema table 17, Record Tables) · 34 data rows (`rectab_id, table_name, record_field_id, parent_id, title, available, private, nrows, notes`) · the 34 linked-record tables (HES inpatient x7, death x2, GP x3, COVID-19 x5, OMOP x16, Olink x2) reachable only through a stub field in `field.txt` (see above); each row's `record_field_id` is that stub's `field_id` · registered 2026-09-21. A different grain from the rest of the dictionary — one row per hospital episode/prescription/event, not one row per participant — flagged for the interview's "tables" question (INTAKE.md Q2). Deferred entirely for now per the steward's 2026-09-21 "decide about this later".
- `record_column.txt` (schema table 18, Data Columns) · 418 data rows (`rectab_id, column_name, value_type, encoding_id, orda, units, notes`) · the actual columns inside each `record_table.txt` table (e.g. `hesin.admidate`, `hesin_diag.diag_icd10`) — none of these 418 columns exist anywhere in `field.txt` · registered 2026-09-21, same deferral as above.
