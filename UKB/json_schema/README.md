# UK Biobank (UKB) — data dictionary as JSON Schema

Generated by the schemify method from the UK Biobank Showcase data dictionary (the 18 schema files listed in section 8) for the CD3 harmonisation project. Written for someone who has neither the skill nor the steward on hand.

## 1. What this package describes

UK Biobank is a UK cohort of about half a million participants. This package describes the part of its participant-level data that the CD3 researchers selected in their second review: the **initial assessment visit** only (what UK Biobank calls instance 0), in the categories they marked as needed. It is not the whole Showcase. The repeat and imaging visits, the 34 linked record tables, and the categories the researchers did not select are out of scope (section 7 gives the counts). The data itself stays inside UK Biobank's Trusted Research Environment (TRE); no participant-level data is in this package, only toy examples.

| Table | Mother file | One row is | Categories | Variables |
|---|---|---|---|---|
| UK Biobank | `uk_biobank/uk_biobank.schema.json` | One participant, identified by `eid`, with the selected fields from the initial assessment visit. | 50 | 4454 |

The categories follow the organisation of the CD3 UKB cohort description exactly: primary category, level 1, level 2, one category per level-2 row (or level-1 row where it has none), in the same order. Each category's title is its path, for example "Assessment centre — Touchscreen questionnaire: Sociodemographics". The variable counts reproduce the researchers' own counts, because a field is in scope only if UK Biobank marks it available (D043); where a count differs it is because some fields exist only at a repeat or imaging visit, or are table-access flags or bulk-file pointers (section 7). The first category, Identification, holds `eid`, which is not a Showcase field.

## 2. Layout and composition

```
common/defs.json                    shared definitions: the Yes/No answer and the eid
uk_biobank/uk_biobank.schema.json   the mother file: an array of participants; each is the allOf of its category files
uk_biobank/categories/*.json        one file per category of variables, plus identification.json
examples/                           toy_valid.json, toy_invalid.json (+ a ledger of seeded violations)
tools/                              validate.py, requirements.txt
dictionary.html                     the browsable data dictionary
playground.html                     an in-browser validator
VARIABLES.csv, ROUTING.csv          the variable inventory and the routing register the validator reconciles
```

A row is the `allOf` union of its categories. Each category lists its own columns, and the mother's single `unevaluatedProperties: false` rejects any column no category declares. Every column is `required`: it is present in every row, and an empty cell is written as `null` (section 4), never left out.

Property names are `f` plus the UK Biobank field id (`f31` is Sex, `f21022` is Age at recruitment), so they stay unique and map straight back to the Showcase (D017). Titles are the dictionary's own wording, verbatim.

## 3. Value-encoding conventions

- **Coded fields** list every code from the source's code list with its label as a `oneOf` branch (`const` + `title`), including UK Biobank's own negative codes where the list has them. **Measures** (numbers) use `anyOf`: a number, or one of the field's named special answers. A numeric field whose code list also names a non-negative answer stays a measure that accepts those named answers (D039).
- **Multi-select questions and per-item lists** are arrays in one field. Each single choice is also listed as a one-item array (`{"const": [3], "title": "…"}`) so the dictionary page shows the options (D031). A list with one entry per reported illness, operation or record may be empty (D039). A list's maximum length is the highest array index minus the lowest plus 1 (D040).
- **Units** are in `x-unit`, exactly as the dictionary states them, never in the title (D018). The Yes/No answer 0/1 is one shared definition, used only where the source's coding is exactly that (D024).
- **Bounds:** none are asserted unless the source states one. The dictionary has no minimum or maximum for continuous fields, so none are invented (D013). An `eid` is a whole number of at least 1.
- **Dates** are text in the form `YYYY-MM-DD`, checked by a pattern. The source does not state the format; it was assumed (D015). **Times and compound values** accept any text because the source states no format (D041).
- **Long code lists.** Where a list has more than 300 codes the schema lists no options and checks only a format taken from the source's own codes (D039, D041, D047): a whole number between the lowest and highest listed code for number codes (the job codes and the verbal-interview illness and medication codes), and a pattern built from the listed codes for text codes (ICD10, ICD9, OPCS4 and the PCT codes). Membership of the list is not checked; a made-up code of the right shape passes.
- **Instances.** Only the initial visit is kept, so an instanced field is one plain column. Its `$comment` says "Initial assessment visit (instance 0)." (D026). Fields that exist only at a repeat or imaging visit are left out (D028).

## 4. Sentinel semantics

This package invents no special code. A field has a special answer only where UK Biobank's own coding gives one, and it is listed with the source's label (D036).

| Code | Meaning | Where it applies |
|---|---|---|
| `null` | An empty cell. Which fields can really arrive blank is not known, so every column except `eid` accepts it (D048, D038) | every column except `eid` |
| `-3` | Prefer not to answer | 532 coded answers across the questionnaires |
| `-1` | Do not know (and a few field-specific variants) | 360 |
| `-2` | Not applicable | 44 |
| `-7` | None of the above | 39 |
| `-10` | Less than one (the unit varies by field) | 29 |
| `-4` | Do not remember, or varies, depending on the field | 14 |

Other negative codes (for example `-121`, `-141`, `-131`, `-11`, `-23`) belong to one field or one code group and carry that field's own label. Read the label, not the number: the same number can mean different things in different fields. `-7` and `-10` are real answers, not missing data. Four of the home-location grid coordinates use `-999`, `-998` and `-997` because UK Biobank's own coding for them (encoding 2535) does.

## 5. Enforced routing rules

Routing policy: **faithful** (D008). Only rules the source states, or the steward tells, are encoded. The dictionary's field-link file (`related.txt`) states who was asked some questions, and the steward chose to enforce them (D049): **87 rules, from 42 gate questions controlling 160 questions** in this package.

How they are written (D051, D048):

- Each rule is a `Questionnaire routing` conditional in the mother file's `allOf`, after the category files. When the gate question holds an answer that excludes the participant, the dependent questions must be **empty (`null`)**. There is no reverse rule, because an empty cell is legal everywhere: a participant who was asked and left it blank is still valid.
- The source gives the condition in words, so the words were turned into codes. "Except those who indicated X" fires on X's code. "Only those who indicated X" fires on every other answer of the gate, including "Do not know" and "Prefer not to answer", since those participants did not indicate X. A multi-select gate fires when its list lacks the code (or contains it, for "except").
- Two readings are deliberately loose, because the wording is ambiguous and the rule fires on fewer answers: R030 ("more often than once or twice a week" does not fire on "Once or twice a week") and R035 ("born outside the United Kingdom" does not fire on "Republic of Ireland").
- A gate that is itself empty never fires a rule.
- Each conditional's `$comment` carries its R id, the source wording and the decision. `ROUTING.csv` is the register; `validate.py routing` reconciles it with the mother.

## 6. Documented but not enforced

- Which fields are asked only of some participants is checked only for the 87 rules in section 5: 83 more links in the dictionary name a gate without stating the answer that routes, so they are not encoded (D050), and one rule names a gate field that does not exist (R009). A row can hold an answer for a question that participant would not have been asked, or `null` where they were.
- Whether a long-code-list code is a real code is not checked, only its shape (section 3).
- A text-valued field has no stated format, so any text is accepted.
- No range check applies to measurements (D013). A value that is possible in form but implausible passes.
- Cross-field consistency, for example ages against dates, is not checked.

## 7. Known source issues handled

- **`f189` and `f22189`** carry the same title (Townsend deprivation index at recruitment). UK Biobank marks `f189` as no longer available, so only `f22189` is included (D014, D043).
- **Array length.** The dictionary's `array_max` is the highest array index, not the count; 132 list properties were first built one entry short and corrected (D040).
- **ICD9 codes** such as `0010` are text and keep their leading zeros. A first pass read them as numbers (D047).
- **Counts match the researchers' selection.** A field is in scope if UK Biobank marks it available, which reproduces their counts in all 53 categories (D043). `VARIABLES.csv` accounts for all 11,821 fields in the dictionary: 4,453 converted, 1,204 deferred and 6,164 not included (5,927 outside the selection, 201 not available, 36 with no initial-visit value).
- **Deferred, not dropped.** Categories the researchers marked "perhaps request later" (Diet 24-hour recall, Accelerometer, Exome, Whole genome), table-access flags and bulk-file pointers (D029), and four cancer-register fields that repeat once per cancer record (D032) are held in `VARIABLES.csv` with the reason, and are converted only if asked (D033).
- **Private fields.** Fields UK Biobank marks private are still included if they are available (D044); their `$comment` says so.
- **Interim genotype release** has 7 variables, matching the researchers' count. The genotyping-intensities sub-category is left out.

## 9. Validating and browsing

```
pip install -r tools/requirements.txt      # or use: uv run tools/validate.py …
python3 tools/validate.py summary .        # schemas, fixtures, coverage — everything
python3 tools/validate.py data . --file your_export.json
```

Validate a **JSON** export (an array with one object per participant). Many columns are lists, which a CSV cannot carry. In a CSV an empty cell is read as `null`. The summary takes about ten seconds because the package is large.

Double-click `dictionary.html` to browse the dictionary (keyword search built in; the Semantic search switch fetches a small model once, then also finds related variables by meaning). Run `python3 -m http.server 8000` from the package root, which serves the whole directory so `assets/vendor/` travels with the page, then open `playground.html`. The `$id` namespace (`https://schemas.example.org/cd3-ukb-pilot/`) is a placeholder to replace before publishing the schemas anywhere public.

## 10. Open items to confirm with the data provider

- **Which fields can really arrive blank (D038, D048).** Every column accepts `null` as the loosest reading. A count of blanks per field from inside the TRE would show which can be tightened, and the package's own validator can report it there.
- **Skipped questions are empty cells (D049).** The 87 rules assume a skipped question is an empty cell. A count from inside the TRE would confirm it.
- **R009's gate.** The source's link names `F903`, which is not a field; the vigorous-activity days question is `f904`. Probably a typo in the source; confirm, and the rule can be encoded.
- **83 gate-only links (D050).** The source says a gate affects who was asked a question but not which answer; the data provider could supply the answers.
- **Date format (D015).** `YYYY-MM-DD` is assumed. Confirm it against a real export.
- **Dictionary page and `null`.** Typed fields show "(nullable)" on the page; coded fields do not list `null` among their valid values.
